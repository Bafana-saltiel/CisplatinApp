# CisplatinApp modular Graph-ML edition

This refactor separates the stable pharmacology workflow from the optional graph-learning workflow.

## Modules

- `R/00_packages.R`: package setup and shared helpers
- `R/01_data.R`: required and optional data loading
- `R/02_reference_regimens.R`: clinical cisplatin reference regimens and cervical model preparation
- `R/03_pharmacology.R`: monotherapy reconstruction, selectable synergy models, reference benchmarking, and candidate ranking
- `R/04_compounds.R`: available third drugs and anti-angiogenic subset
- `R/05_validation.R`: target parsing, CRISPR dependency, expression, and mutation evidence
- `R/06_graph_ml.R`: graph construction, node features, graph propagation, and optional torch GCN
- `R/07_ui.R`: Shiny user interface
- `R/08_server.R`: Shiny server, plots, tables, and downloads

## Required data

Place these files in `data/`:

- `PortalCompounds.csv`
- `Model.csv`
- `GDSC2ResponseCurves.csv`

Optional evidence layers:

- `CRISPRGeneDependency.csv`
- `OmicsExpressionTPMLogp1HumanProteinCodingGenesStranded.csv`
- `OmicsSomaticMutationsMAF.maf`

## Run

```r
shiny::runApp()
```

## Graph-learning interpretation

The graph module predicts whether a candidate is stronger than the model-specific reference using labels generated by the current reconstructed pharmacology analysis. It is an internal ranking layer, not an externally validated clinical predictor. The transparent graph-propagation engine works without `torch`. The GCN engine requires the optional R `torch` package.

## Fixes in this refactor

- Replaced scalar `case_when()` drug-ID dispatch with `switch()` to remove the dplyr 1.2 deprecation warning.
- Renamed and hardened the gene-target parser as `extract_target_genes()`.
- Removed formula-based `purrr::discard()` calls from target and graph token parsing to prevent language-object comparison errors.
- Isolated graph-learning functions from target annotation and pharmacology functions to avoid namespace collisions.

## Connect Cloud deployment

Do not call `install.packages()` or `torch::install_torch()` from `app.R` or any sourced module. Connect Cloud restores packages before the worker starts, based on `manifest.json`.

From the application root on your local machine, run:

```r
install.packages(c("igraph", "rsconnect"), repos = "https://cloud.r-project.org")
source("generate_manifest.R")
```

Commit the regenerated `manifest.json` together with the application files and redeploy.

`torch` is optional. If it is not present in the deployment environment, the app automatically uses graph propagation. To request the GCN engine on Connect Cloud, install `torch` locally before regenerating the manifest; successful cloud restoration still depends on the platform supporting the package and its native runtime dependencies.
